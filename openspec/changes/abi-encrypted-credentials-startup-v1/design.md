## Context

Эксперимент на Docker Desktop подтвердил передачу через stdin в tmpfs, очистку при остановке и SIGKILL, а также `memory.swap.max=0` при равных лимитах памяти и swap. Docker Desktop отклонил опцию `noswap` для самого тома.

## Goals / Non-Goals

Защищённый запуск добавляется в существующий ABI. Границы объёма и совместимости описаны в proposal.md.

## Decisions

1. **Файловый загрузчик.** Явный защищённый режим выбирает пару путей к файлам. Загрузчик вызывается до `startServer`, проверяет оба файла и отклоняет смешивание файлового режима с ключами из окружения. Он читает файлы, а одноразовый стартовый механизм удаляет их до запуска сервера. Каталог tmpfs доступен только UID ABI. Право записи в каталог нужно для подготовки и удаления файлов. Сами опубликованные файлы ABI открывает только на чтение.
2. **Ручная разблокировка.** Утилита `age` на Mac запрашивает пароль в терминале и расшифровывает стандартный файл `.age`. Команда запуска буферизует весь результат в памяти и проверяет код завершения `age` и содержимое пары перед запуском Docker. Команда передаёт его одним потоком stdin без TTY и без секретов в аргументах, окружении или временных файлах на хосте. Приёмник внутри контейнера проверяет полноту пакета и записывает пару в закрытый временный каталог на том же tmpfs. Переименование каталога одним действием публикует готовую пару. ABI ждёт публикации с конечным таймаутом, затем читает и очищает файлы до старта HTTP. При отказе команда останавливает и удаляет свой контейнер. Таймаут закрывает также случай, когда команда исчезла до публикации. Обычное завершение, обрыв передачи и повторный запуск проверяются отдельно.
3. **Отдельный Compose-проект.** Команда использует собственный Compose-файл, отдельное имя проекта, отдельный каталог корреляции под BBB data root и отдельный адрес доступа для smoke. Это отделяет контейнер от выбора сервисов и `--remove-orphans` в Demo workflow. Конфигурация задаёт `restart: "no"`, запуск без root и лишних capabilities, корневую ФС только для чтения, отключение core dumps, отдельные точки записи для данных и tmpfs. Устанавливаем равные лимиты памяти и swap и проверяем фактический cgroup до подачи секрета. Отсутствующий или ненулевой `memory.swap.max` блокирует запуск.

## Risks / Trade-offs

- Остановка процесса требует нового ввода пароля. Оставшиеся на Bybit заявки и позиции требуют действующего порядка восстановления.
- Удаление файлов освобождает пути, но значения остаются в памяти ABI. Проверка cgroup относится к Linux VM. Поведение подкачки macOS не проверено.
- Работающий ABI, пользователь `mcroma` и Docker daemon входят в границу доверия. Runner выполняет Demo deploy от `mcroma` и имеет доступ к тому же daemon. Отдельный Compose-проект защищает от штатных операций Demo, но не ограничивает полномочия runner.

## Migration Plan

Проверить новый путь на отдельном Demo с изолированным торговым состоянием, включая полный smoke и проверку отсутствия оставшихся заявок и позиций. Для отката остановить защищённый проект. Текущий Demo использует свой обычный запуск. Включение Mainnet требует отдельного изменения и согласования.
