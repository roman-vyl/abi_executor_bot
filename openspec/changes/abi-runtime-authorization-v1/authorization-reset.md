# Решение о чистом старте авторизации

Принято 2026-11-05. Новая функциональность начинается от актуального main. PR #51 исключён из основы реализации. PR #49 служит справочником по age. Runtime PR #46 сохраняется. Общий план ниже в прежних артефактах подлежит последующей синхронизации с этим решением перед следующими шагами.

## Граница ответственности

AuthorizationService является единственным владельцем кандидата, подтверждённой пары и состояния авторизации. Он получает verify(candidate) и знает только accepted, rejected, temporary_failure. Verifier отвечает за подтверждение credentials, expected UID и прав. Сам сервис не имеет импортов Bybit, HTTP, журнала, readiness или trading-компонентов.

Composition root организует последующее подключение REST/WS и существующее восстановление торгового состояния. Account API использует единую авторизацию и ограничения своей операции. Trade-cycle API дополнительно требует независимой готовности correlation journal и существующих проверок привязок. Единственный механизм допуска использует предикаты соответствующей категории операции.

В новой версии предусмотрен один штатный источник credentials — AuthorizationService. Прежний образ и его конфигурация служат для отката.

## Проверенный первый шаг

ABI PR #52, коммит 01dffaa, основан на main 0d8a111. Diff состоит из одного компонента и его тестов. Интеграция с composition root, REST, HTTP, Docker и журналом относится к следующим отдельно принимаемым шагам.

Интерфейс состоит из status(), authorize(candidate), retry(), credentials(). Credentials копируются по двум строковым полям и замораживаются Object.freeze. До AUTHORIZED credentials() возвращает undefined.

Правила конкуренции определены явно. VERIFYING допускает одну активную проверку, другие попытки получают busy. После temporary_failure сохраняется один кандидат, новая authorize получает retry_required, retry проверяет сохранённую пару. Rejected удаляет кандидата. В AUTHORIZED authorize и retry возвращают already_authorized без замены пары. Исключение verifier консервативно обрабатывается как temporary_failure.

Проверки прошли — 13 изолированных тестов, 1072 теста полного npm test, typecheck и build. Приёмка шага ожидается.

## Последующие границы

3. Затем согласовать admission, торговую готовность, Runtime и обычный Deploy Demo.

Каждый шаг имеет отдельное разрешение и ревью. Эксплуатационная интеграция выполняется на Demo после согласованного завершения серии. Mainnet запрещён.
