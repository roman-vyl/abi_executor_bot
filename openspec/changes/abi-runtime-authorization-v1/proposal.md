> Актуальное решение о чистом старте и границах первого шага записано в [authorization-reset.md](authorization-reset.md). Предыдущие артефакты ниже требуют синхронизации с этим решением перед дальнейшей реализацией.

## Why

Оператор должен запускать весь BBB обычным Deploy и разблокировать торговлю в любой момент после запуска. Ожидание пароля внутри старта контейнера мешает штатному деплою и восстановлению сервисов.

## What Changes

- ABI запускается в LOCKED, обслуживает HTTP и локальный журнал, принимает позднюю авторизацию через Unix socket.
- age расшифровывает пару на Mac, команда передаёт её работающему ABI через stdin локального docker exec.
- Допуск к торговой команде атомарно отделяет гарантированный отказ до исполнения от существующей обработки неопределённых результатов.
- Runtime распознаёт execution_not_ready и снимает только маркер entry-попытки, гарантированно отклонённой до исполнения.
- bbb_stack использует обычный деплой всех сервисов и liveness ABI для Docker. Авторизация доступна отдельно.
- Изменения заменяют startup-барьер и одноразовую файловую доставку PR #49, а также интерактивную ветку деплоя PR #103.

## Capabilities

### New Capabilities

- `runtime-authorization` — поздняя авторизация, атомарный допуск, отсутствие очереди и ограниченное взаимодействие с существующим reconciliation Runtime.

### Modified Capabilities

- `container-runtime` — разделение liveness и execution readiness.
- `abi-entry-package-api` — типизированный отказ до исполнения.
- `abi-open-position-lookup-api` — типизированная временная неготовность.
- `abi-entry-cycle-recovery-api` — типизированная временная неготовность.
- `abi-position-management-api` — типизированный отказ до исполнения.

## Impact

ABI затрагивает конфигурацию, composition root, REST-адаптер, активацию приватного WS и наблюдательного REST reconciler, readiness и маршруты. Runtime затрагивает модели/декодеры ответов, entry bridge и _execute_one. bbb_stack затрагивает healthcheck и обычный Deploy Demo.

Новые сервисы, торговые состояния Runtime, очереди торговых команд, новый recovery-протокол и реестр аккаунтов вне объёма. Расчёт позиции, идентификаторы заявок и формат корреляционного журнала сохраняются. Историческая сверка журнала не становится условием допуска торговли. Mainnet guard сохраняется, эксплуатационный переход ограничен Demo. Существующие dry-run и env-based запуск остаются совместимыми.
